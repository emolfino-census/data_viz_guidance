# 508 Compliance

## Purpose and Overview

This section highlights the requirements for Section 508 compliance for data visualizations. Section 508 is the federal law that requires government information technology, including web content, to be accessible to people with disabilities. All visualizations shared publicly on the web must follow these requirements. For more information, see the latest version of the [Web Content Accessibility Guidelines (WCAG) 2.1 AA](https://www.w3.org/TR/WCAG21/).

## When This Guidance Applies

Apply this guidance to every chart, map, table, and dashboard shared publicly on the web, whether static or interactive.

In addition to the guidance provided in this section, relevant guidance can also be found in the Color, Interactive Chart, Mobile Design, Note, and Typography sections.

## Essential Requirements

### Alt Text

Alt text should always be used for data visualizations. Alt text provides information for people who are blind or have low vision and use screen readers. It must give enough information to understand the main message of the chart or graph. If this is not possible, data tables may be required.

### Data Tables

Data tables may be provided in addition to alt text for any visualization to convey its full meaning to users with visual impairments. Visually complex charts or graphs require data tables that break down the information shown in order to meet Section 508 and WCAG guidelines. For help meeting this requirement, reach out to the Section 508 Program Office at census.508.accessibility@census.gov or to Tamika Lewis of the Section 508 Program Office.

### Images and Images of Text

Images and images of text must be able to be resized up to 200 percent without loss of content or functionality. For help meeting this requirement, reach out to the Section 508 Program Office at census.508.accessibility@census.gov or to Tamika Lewis of the Section 508 Program Office.

### Color Accessibility

There are many considerations for the use of color within data visualizations. WCAG makes sure content is accessible to everyone. To meet these standards, text should have a color contrast ratio of [at least 4.5:1](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) (WCAG 1.4.3). This makes sure viewers who cannot see the full color spectrum can read the text or image. See the [Color](color.html) page for more information.

## Recommended Practices

* Write alt text that states the chart type, the topic, and the main takeaway, not only the title.
* Keep alt text short, and put full details in a data table or a longer description below the chart.
* Do not use color as the only way to show meaning (WCAG 1.4.1). Add direct labels, patterns, or text.
* Give chart lines, bars, and other graphic parts a contrast ratio of at least 3:1 against nearby colors (WCAG 1.4.11).
* Make sure every interactive feature, such as filters, buttons, and hover details, can be used with a keyboard (WCAG 2.1.1).
* Use real text for titles, labels, and notes instead of text inside images when possible.
* Test with a contrast checker, such as the [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/), and with a screen reader before release.

## Practices to Avoid

* Do not use alt text such as "chart" or "image" that gives no information.
* Do not repeat every number in alt text when a data table would be clearer.
* Do not use red and green as the only way to tell groups apart.
* Do not put essential information only in hover popups.
* Do not publish images of text that become blurry or cut off when zoomed to 200 percent.

## Common Errors and Misinterpretations

| Issue | Why It Matters | Recommended Correction |
|---|---|---|
| Missing or empty alt text | Screen reader users get no information. | Add alt text with the chart type, topic, and main takeaway. |
| Alt text repeats only the title | Users miss the main message. | Describe what the data show. |
| Low text contrast | Text is hard or impossible to read. | Use at least 4.5:1 contrast. |
| Color is the only way to show groups | Readers with color blindness cannot tell groups apart. | Add labels, patterns, or text. |
| Complex chart with no data table | Users cannot get the full information. | Provide a data table or link to one. |

## Publication Quality Checklist

- [ ] The visualization fits the analytical question.
- [ ] Relevant alternatives were considered.
- [ ] Data source, geography, reference period, and units are documented.
- [ ] Data transformations and aggregation are appropriate.
- [ ] Missing values and relevant uncertainty are addressed.
- [ ] Existing accessibility, scaling, and axes guidance has been followed.
- [ ] Chart-specific limitations and caveats are explained.
- [ ] Code examples have been executed and verified.
- [ ] The visualization has undergone the appropriate review.
